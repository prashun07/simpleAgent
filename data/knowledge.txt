# Simple Agent Project - Knowledge Base

This file is the "source of truth" for our RAG agent. When you ask a question,
the agent searches this text for relevant passages and uses them to answer.

## What is RAG?

RAG stands for Retrieval-Augmented Generation. It is a pattern that combines:

1. RETRIEVAL - Find relevant documents from a knowledge base using embeddings
2. AUGMENTATION - Add those documents to the LLM prompt as context
3. GENERATION - Ask the LLM to answer using only that context

RAG helps LLMs answer questions about YOUR data (not just what they learned in training).

## How This Project Works

- Documents live in the data/ folder (like this file).
- Text is split into small chunks (about 500 characters each).
- Each chunk is converted to a vector (embedding) using Gemini Embeddings API.
- Vectors are stored in an in-memory vector database.
- When you ask a question, the most similar chunks are retrieved.
- Those chunks are sent to Gemini along with your question.

## Project Files

- main.py: Entry point. Starts the chat loop.
- rag_agent.py: The RAG agent (retrieve -> augment -> generate).
- tool/langchainloader.py: Loads and indexes documents.
- agent.py: Original simple agent (rule-based + direct LLM, no RAG).
- data/knowledge.txt: Local knowledge for RAG queries.
- .env: Stores GEMINI_API_KEY (never commit this file).

## Gemini Models Used

- LLM (generation): gemini-2.5-flash - fast, good for chat
- Embeddings: models/gemini-embedding-2 - converts text to vectors for search

## Tips for Beginners

- RAG does NOT magically know everything. It only knows what is in your documents.
- Better documents = better answers. Add more .txt files to data/ to expand knowledge.
- Chunk size matters: too small loses context, too large retrieves irrelevant text.
- Always check if the answer is actually supported by your source documents.
